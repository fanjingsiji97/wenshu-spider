# 裁判文书网判例采集与结构化（wenshu-spider）

面向「盗窃罪量刑」研究场景的数据采集项目。累计承接 **4 个委托单**：前 3 单交付
「爬取 + 清洗」的数据集，第 4 单追加**工具化**——把整套流程封装成桌面软件交付。

最终产出：**5,137 篇裁判文书，31 个字段的结构化数据集**。

---

## 一、技术上最难的一步：请求参数 3DES 加密

文书网的搜索接口不接受明文参数。每次请求都需要一个 `ciphertext` 字段：

```
ciphertext = salt(24位随机) + iv(8位日期) + base64(3DES_CBC(timestamp))

其中：
  key = salt           (24 字节，正好满足 3DES 的 24 字节密钥长度)
  iv  = YYYYMMDD       (8 字节，随日期变化)
  明文 = 毫秒级时间戳
```

**关键难点**：拼接完成后还要把整个字符串**逐字符转成二进制**、用空格连接：

```python
def str_to_binary(s: str) -> str:
    result = []
    for i, ch in enumerate(s):
        if i != 0:
            result.append(" ")
        result.append(bin(ord(ch))[2:])
    return "".join(result)
```

这一段是直接对照前端 JS 的 `cipher()` 函数复刻的——**逐字符比对输出**才确认
Python 端与浏览器端生成完全一致。

同时还要生成 `__RequestVerificationToken`（另一个 24 位随机串）。

> 见 `src/wenshu_spider.py` 中的 `generate_ciphertext()` / `generate_token()`。

## 二、风控：UA 绑定 + 频率限制

实测发现两个约束：

1. **UA 与 ciphertext 绑定**。`ciphertext` 生成时与 User-Agent 存在依赖关系，
   换成别的 UA 直接失败。所以工具里 UA 固定写死，不做轮换。
2. **站点有访问频率风控**。连续高频请求会让会话（SESSION）失效。

应对策略不是「加大重试次数」，而是**主动降低请求节奏**。核心是
`HumanSimulator` 类（`src/wenshu_spider.py`）：

| 机制 | 实现 |
|---|---|
| 基础延迟 | 指数分布 `random.expovariate()`，均值随请求数缓慢上升（1.5s → 2.7s） |
| 偶发长停顿 | 15% 概率 +3~12s，3% 概率 +10~30s |
| 工作时间窗 | 只在 6:00–23:00 高频请求，其余时段延迟 ×2.5 |
| 周期性休息 | 每 30 次请求长休 60~300s；每 10 次短休 5~20s |

**设计意图**：让请求间隔的统计特征接近真人浏览，而不是均匀高频。

## 三、会话失效的处理原则

这一点是这个项目里我最坚持的设计：

```
请求 → 判定 code != 1
      → 检查 description 是否含「登录 / 认证 / 失效」
      → 是：立即中断任务，提示使用者手动更新 SESSION
      → 否：记录服务端错误，继续
```

**不盲目重试**。因为反复用失效凭据请求，很可能让账号状态彻底打坏，
到那时连人工更新都救不回来。宁可停下来，等人换 Cookie 再续跑。

## 四、断点续爬

长任务必须能从任意位置恢复。实现基于三个状态文件：

| 文件 | 作用 |
|---|---|
| `progress.json` | 每个（省份 × 关键词）组合已翻到第几页 |
| `crawled_ids.json` | 已采集的文书 docId 集合，用于去重 |
| `WENSHU.csv` | 追加写入的结果，不覆盖 |

## 五、从非结构化文本抽取结构化字段

判决书全文是一大段自然语言，需要抽成可分析的列。以 `MERGE.py` 为例：

**出生年份**——覆盖 6 类表述模板：

```python
patterns = [
    r'出生于\s*(\d{4})',
    r'出生\s*[：:]\s*(\d{4})',
    r'[（(](\d{4})年\d{1,2}月',
    r'(\d{4})年\d{1,2}月\d{1,2}日',
    r'男,\s*(\d{4})',
    r'女,\s*(\d{4})',
]
```

**盗窃金额**——覆盖 4 类模板，并过滤噪声：

```python
if amount >= 10:      # 过滤 <10 元的误匹配（多为条款编号、日期等）
    return amount
```

## 六、工具化（第 4 单的交付形态）

前 3 单交付的是 CSV / Excel；第 4 单对方希望**自己也能跑**，所以封装成
tkinter 桌面程序：

- 关键词组与省份范围可勾选
- 运行日志实时回显（搜索 / 详情 / 状态三类回调）
- 内置 SESSION 输入框，会话失效时可直接在界面更新
- 进度自动保存，关闭后重开可续跑

## 复现说明

`src/` 中的 `SESSION` 已替换为占位符 `<YOUR_SESSION_HERE>`。
运行前需要：

1. 浏览器登录裁判文书网
2. 从开发者工具复制 `SESSION` Cookie 值
3. 填入代码或 GUI 的 SESSION 输入框

> 注意：本项目仅用于公开裁判文书的研究性采集。实际使用须遵守目标站点的
> robots 协议与服务条款，控制请求频率，不得用于商业转售。
